# Реестр научных проектов Южного университета (ИУБиП)

Электронная информационная система «Реестр научных проектов» — единый рабочий
инструмент, в котором научная инициатива проходит путь от постановки
исследовательского вопроса до подтверждённого результата.

Разработано по техническому заданию **версии 1.0 от 06.10.2026**.

| Параметр | Значение |
|---|---|
| Краткое наименование | Реестр научных проектов (РНП) |
| Заказчик | Южный университет (ИУБиП) |
| Функциональный заказчик | Проректор по науке и метакомпетенциям Б. В. Мартынов |
| Разработчик | Д. И. Орлов |
| Версия системы | 1.0.0 |
| Рабочий адрес | `science.iubip.ru` (домен на согласовании) |
| Публичный API | `/api/public/v1` (только чтение) |

## Архитектура

Модульное веб-приложение в одной кодовой базе и одна реляционная база данных —
прямое требование п.3.1 ТЗ.

```
                    ┌──────────────────────────────────────┐
   Браузер ────────►│  nginx (HTTPS, редирект с HTTP)      │
   закрытая зона    │  ограничение частоты, CSP, HSTS      │
                    └──────────────┬───────────────────────┘
                                   │ 127.0.0.1:8000 (не публикуется)
                    ┌──────────────▼───────────────────────┐
                    │  FastAPI                             │
                    │  /api            закрытая рабочая зона │
                    │  /api/public/v1  публичная витрина    │
                    └──────────────┬───────────────────────┘
                                   │
                    ┌──────────────▼───────────────────────┐
                    │  SQLite (WAL, по соединению на поток) │
                    └──────────────────────────────────────┘
```

| Компонент | Назначение |
|---|---|
| Закрытая рабочая зона | Карточки, экспертизы, решения, панели, импорт, администрирование |
| Сервер приложения | Проверка прав, маршрутов, обязательных полей, расчёт сроков, формирование отчётов |
| Реляционная база данных | Структурированные сведения и связи; прямой внешний доступ запрещён |
| Файловое хранилище | Ссылки во всех очередях; защищённые файлы — вторая очередь |
| Публичная проекция | Отдельное представление только утверждённых открытых полей |
| Журнал аудита | Неизменяемая история ключевых операций |

### Стек

| Слой | Технология | Обоснование |
|---|---|---|
| Сервер приложения | Python 3.11+ / FastAPI | Синхронный код с `threading.local` соединением БД; минимум внешних зависимостей |
| База данных | SQLite 3 (WAL) | Прямо разрешена п.3.1; достаточна для 2 000 пользователей, 10 000 проектов и 100 000 связанных записей (NFR-05) |
| Интерфейс | React 18 + TypeScript + Vite | Сборка в статику, отдаётся тем же приложением |
| Обмен | openpyxl (XLSX), csv | Требуется п.7.2 |

Стек согласован с заказчиком при постановке задачи (вопрос 3 ТЗ).

## Быстрый запуск для разработки и приёмки

```bash
git clone https://github.com/Eagle1man/reestr-nauchnyh-proektov.git
cd reestr-nauchnyh-proektov

python -m venv .venv
.venv\Scripts\pip install -r backend\requirements.txt      # Windows
# .venv/bin/pip install -r backend/requirements.txt         # Linux

cp .env.example .env
# В .env обязательно задать SECRET_KEY:
#   python -c "import secrets; print(secrets.token_urlsafe(48))"

# Справочники, настройки, программы, учётные записи, демо-проекты
.venv\Scripts\python backend\scripts\seed.py --with-users --with-demo

# Интерфейс
cd frontend && npm install && npm run build && cd ..

# Сервер
cd backend && ..\.venv\Scripts\python -m uvicorn app.main:app --port 8000
```

Рабочий адрес: `http://127.0.0.1:8000`
Открытый раздел: `http://127.0.0.1:8000/public`
Документация API: `http://127.0.0.1:8000/api/docs`

**Учётные записи пилотного набора** (`--with-users`) создаются с ролью
«требуется смена пароля». Пароль задаётся переменной `SEED_PASSWORD` при
запуске сида; если она не задана, пароль генерируется и печатается один раз.

## Безопасность

Секреты не хранятся в репозитории: `.env` в `.gitignore`, `.env.example`
содержит только имена параметров. Пароли хешируются PBKDF2-HMAC-SHA256
(260 000 итераций) и показываются пользователю один раз — при создании
учётной записи и при сбросе. В журнал аудита попадает факт операции, а не её
секретное содержимое.

Файл `.gitattributes` задаёт `* text=auto eol=lf`: репозиторий на Windows
разрабатывается под развёртывание на Linux, и CRLF в скриптах и конфигурациях
nginx там ломает исполнение.
