# Руководство пользователя

Реестр научных проектов Южного университета (ИУБиП).

Руководство предназначено для руководителей проектов, участников команд,
кураторов программ, экспертов, обучающихся и аспирантов.

---

## 1. Вход и выход

Вход выполняется по университетской учётной записи или служебному логину и
паролю. Пароль выдаёт технический администратор при первом входе.

| Правило | Значение |
|---|---|
| Длина пароля | не менее 12 символов: строчные и прописные буквы, цифры, спецсимволы |
| Блокировка | после 5 неудачных попыток вход блокируется на 15 минут |
| Сессия | завершается после 60 минут бездействия |
| Смена пароля | в разделе «Профиль» |

Если пароль сброшен администратором, система потребует сменить его при первом
входе. Сообщение «неверный логин или пароль» намеренно одинаково для неверного
пароля и несуществующего логина: это не позволяет перебирать учётные записи.

---

## 2. Что видно вам в зависимости от роли

Права определяются ролью **и** вашим отношением к конкретному проекту.

| Ваша роль | Что доступно |
|---|---|
| Руководитель проекта | Карточка, команда, задачи, сроки, данные, риски, результаты; подтверждение вклада |
| Участник проекта | Порученные задачи, контрольные точки, подтверждающие материалы |
| Куратор программы | Паспорт программы, запуск и приёмка упрощённых проектов, рекомендации по полному маршруту |
| Эксперт | Только назначенные материалы и заключение по своему объекту |
| Секретарь Научного совета | Проверка комплектности, сроки, напоминания, регистрация решений, панели, публикация разрешённых данных |
| Проректор по науке | Запуск, приостановление и приёмка проектов полного маршрута, критические отклонения |
| Ректор | Весь портфель, панель ректора, решения по дополнительным ресурсам и рискам |
| Научный совет | Квартальный обзор, стратегические и исключительные случаи |
| Технический администратор | Учётные записи, настройки, резервное копирование; научных решений не принимает |

Если действие недоступно, система объясняет причину: например
«действие доступно секретарю Научного совета» или «не заполнены обязательные
поля: Команда, Контрольные точки».

**Вы не можете** править чужую карточку, менять итоговое решение по своему
собственному проекту и оценивать проект, в котором вы участвуете.

## 3. Создание карточки проекта

Раздел «Проекты» → «Создать карточку».

### Обязательные поля

**Паспорт:** полное название, краткое название, научная программа, связь с
общей темой, плановые даты, руководитель, режим публикации.

**Шесть обязательных научных полей** — это требование п.4.2 ТЗ для запуска
упрощённого проекта:

1. Исследовательская проблема — проверяемая проблема, а не общая тема
2. Вопрос или гипотеза
3. Цель — одна основная цель
4. Методы — не менее одного
5. Данные или доказательная база — источник, состав, период, доступ
6. Критерии результата — не менее одного признака выполнения

Для **полного** маршрута дополнительно обязательны объект, предмет, задачи,
научная новизна, практическая применимость, ограничения, конфиденциальность
и права, ресурсный запрос.

Поля, обязательные при выбранных признаках (например, пояснение при
персональных данных), отмечаются в перечне незаполненных полей.

### Проверка дублей

Пока вы набираете название, система показывает похожие проекты: точное
совпадение, вхождение названия в другое или совпадение трёх и более ключевых
слов. Если это другая инициатива, нажмите «Это другая инициатива — создать»:
решение будет зафиксировано в журнале. Если это дубль, откройте найденный
проект и не создавайте второй.

### Номер проекта

Номер вида `РНП-2026-0001` присваивается автоматически и не меняется.
Числовой номер не переиспользуется после архивирования.

## 4. Маршрут проекта

Маршрут — упрощённый или полный. **Система предлагает маршрут сама** по
признакам, которые вы отмечаете:

| Код | Признак полного маршрута |
|---|---|
| T-01 | Внешнее финансирование, партнёр или договорные обязательства |
| T-02 | Персональные данные, участие людей в исследовании, этическое рассмотрение |
| T-03 | Запрос ресурсов сверх утверждённого лимита |
| T-04 | Критичная инфраструктура или повышенный риск |
| T-05 | Продукт для внешнего применения |
| T-06 | Конфиденциальные данные, интеллектуальные права, ограничение публикации |

Междисциплинарность сама по себе основанием для полного маршрута **не**
является.

Если вы меняете предложенный маршрут вручную, требуется комментарий — он
попадает в журнал. Окончательный маршрут фиксирует уполномоченное лицо.

## 5. Жизненный цикл проекта

```
Черновик → Проверка комплектности → [Проверка комплектности]
                                      ↓
                        ┌─────────────┴─────────────┐
                        │                           │
              На доработке              Запустить (куратор, упрощённый)
                        │              Назначить экспертизу (полный)
                        └─────────────┬─────────────┘
                                      ↓
                      Активен ←→ Приостановлен
                        ↓              ↓
             Представить результат   Резерв / Закрыт
                        ↓
              Итоговая экспертиза
                   ↓          ↓
              Завершён   На доработке
```

Действия доступны только в соответствующем статусе и только вашей роли.
Недопустимый переход блокируется с объяснением причины.

### Сроки обработки

| Операция | Срок | Ответственный |
|---|---|---|
| Проверка комплектности | до 3 рабочих дней | Секретарь |
| Принятие задания либо самоотвод экспертом | до 1 рабочего дня | Эксперт |
| Экспертиза | до 10 рабочих дней | Эксперт |
| Решение по заключению | до 5 рабочих дней | Куратор или проректор |
| Реакция на жёлтый риск | 5 рабочих дней | Руководитель |
| Рассмотрение красного риска | 5 рабочих дней | Проректор |

## 6. Контрольные точки

Каждая точка — проверяемое событие с плановой датой, ответственным и
**плановым подтверждением**. Формулировка «выполнение работы» без доказательства
недопустима: при выполнении обязательны фактическая дата и подтверждение.

Если срок переносится, **обязательна причина переноса** — она сохраняется в
истории точки вместе с прежним и новым сроками.

Просрочка считается автоматически в рабочих днях.

---

## 7. Индикатор риска и статус — это разные вещи

Проект может быть «Активен» и при этом иметь жёлтый индикатор риска.

| Индикатор | Когда | Что делать |
|---|---|---|
| Зелёный | Работа по плану, подтверждения актуальны | Ничего, сводный учёт |
| Жёлтый | Нет подтверждения в срок, задержка до 20 рабочих дней | Руководитель за 5 рабочих дней указывает причину, меры и новый срок |
| Красный | Задержка более 20 рабочих дней, повторный срыв, потеря данных или руководителя, высокий риск | Проректор рассматривает за 5 рабочих дней, может приостановить проект |

Ручное изменение индикатора требует комментария.

## 8. Экспертиза

### Если вы эксперт

1. В разделе «Назначения» найдите назначение.
2. В течение одного рабочего дня подтвердите отсутствие конфликта интересов
   либо заявите самоотвод.
3. Подготовьте заключение из **четырёх обязательных блоков**:

| Блок | О чём |
|---|---|
| Соответствие цели | Связан ли вопрос с целью и заявленным результатом |
| Метод и данные | Достаточны ли метод, данные или доказательная логика |
| Качество результата | Подтверждён ли результат, соответствует ли критериям |
| Риски и ограничения | Есть ли условия, препятствующие запуску, публикации, применению |

4. Итоговая рекомендация: поддержать / поддержать с условиями / вернуть на
   доработку / не поддерживать.

**После фиксации заключение не редактируется.** Опечатку исправляют новой
версией — исходное заключение сохраняется.

Самоотвод необратим: событие остаётся в журнале. Вам назначат другого эксперта.

Вас не назначат экспертом по проекту, в котором вы участник, предполагаемый
соавтор, научный руководитель участника или куратор программы.

## 9. Результаты

Результат — самостоятельная подтверждаемая запись. Обязательны: вид, название,
описание, авторы из профилей, стадия готовности, критерий приёмки, связь хотя
бы с одним проектом.

**Один результат может быть связан с несколькими проектами и при этом
учитывается в общей статистике один раз.** Например, статья по итогам двух
проектов — одна запись результата, одна работа в портфеле.

Проверка дубля: по DOI, EDN, а также по совпадению названия, авторов и года.
Если найден возможный дубль, подтвердите создание — решение попадёт в журнал.

Для принятого результата обязательны фактическая дата и подтверждающий
материал. Без заключения эксперта результат не считается подтверждённым.

### Публикации

Стадии идут отдельно: замысел → внутренняя экспертиза → подана → доработка →
принята → опубликована. С момента подачи обязательны целевое издание и
фактическая дата подачи.

---

## 10. Публикация и открытый раздел

**До утверждения данные закрыты.** Вы выбираете режим публикации —
«не публиковать», «проект», «результаты» или «всё», но передача в открытый
раздел происходит только после отдельного разрешения уполномоченного лица.

В открытый раздел **не попадают** никогда: внутренние комментарии, экспертные
заключения, история согласований, риски, ресурсные запросы, персональные
контакты, закрытые файлы, конфиденциальные сведения о партнёрах, журнал
действий.

Отзыв разрешения немедленно исключает объект из открытого контура.

---

## 11. Импорт данных

Раздел «Импорт и выгрузка».

1. Скачайте шаблон формы инвентаризации.
2. Заполните его по образцу на втором листе шаблона.
3. Загрузите файл и нажмите «Проверить файл».

До подтверждения **рабочие данные не изменяются**. Вы увидите число корректных
строк, строк с предупреждениями, строк с ошибками и возможных дублей. По каждой
строке с ошибкой указано поле и причина — исправьте её в файле и загрузите снова.

Строки с ошибками не загружаются. Профили людей и программы не дублируются:
система находит существующие по служебному адресу или Ф. И. О.

---

## 12. Напоминания

Раздел «Назначения» собирает всё, что требует вашего действия: истёкшие
сроки экспертиз, проекты с жёлтым и красным риском, карточки, ожидающие
проверки комплектности, диссертации, допущенные к защите.

Электронная почта для этого используется во второй очереди; пока всё внутри
системы.

---

## 13. Что делать, если система не даёт действие

Система всегда объясняет отказ. Типовые причины:

| Сообщение | Что делать |
|---|---|
| «Не заполнены обязательные поля: …» | Заполните перечисленные поля |
| «Действие доступно секретарю Научного совета» | Обратитесь к секретарю |
| «Заключение не является положительным» | Приёмка возможна только по рекомендации «Поддержать» или «Поддержать с условиями» |
| «Причина переноса обязательна» | Укажите причину изменения срока |
| «Ручное изменение маршрута требует комментария» | Опишите, почему маршрут другой |
| «Выявлены признаки полного маршрута» | Проект переводится на полный маршрут, обратитесь к проректору |
| 403 «Недостаточно прав» | Ваша роль не даёт права на операцию |
| 409 «Карточка изменена после вашего открытия» | Другой пользователь уже сохранил правку. Обновите страницу |

Если причина неясна, обратитесь к секретарю Научного совета. Полный журнал
действий доступен техническому администратору, секретарю и руководству.
