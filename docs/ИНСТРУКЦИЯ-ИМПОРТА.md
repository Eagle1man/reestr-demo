# Инструкция по импорту ранее собранных данных

Позиция 8 комплекта поставки (п.15 ТЗ), раздел 7.2 ТЗ.

---

## 1. Назначение

Импорт нужен один раз: чтобы перенести в реестр проекты, собранные до появления
системы — из таблиц, документов или анкет. После переноса реестр становится
единственным источником сведений, и повторный ввод извне не требуется.

Второе назначение — плановое заполнение карточек при инвентаризации.

---

## 2. Форма инвентаризации

Шаблон скачивается из интерфейса: **«Импорт и выгрузка» → «Скачать шаблон
формы»** или `GET /api/import/template`.

### Колонки

Порядок колонок в шаблоне совпадает с обязательными полями MVP (п.7.2 п.1).

| # | Колонка | Обязательна | Код ТЗ | Формат |
|---|---|---|---|---|
| 1 | Полное название | да | A-02 | текст до 500 знаков |
| 2 | Краткое название | да | A-03 | текст до 150 |
| 3 | Код программы | да | A-05 | код существующей программы |
| 4 | Руководитель, Ф. И. О. | да | A-12 | Ф. И. О. или служебный адрес |
| 5 | Служебный адрес руководителя | нет | — | ключ сопоставления профиля |
| 6 | Плановое начало | да | A-11 | `ГГГГ-ММ-ДД` |
| 7 | Плановое завершение | да | A-11 | `ГГГГ-ММ-ДД` |
| 8 | Исследовательская проблема | да | A-17 | до 2000 знаков |
| 9 | Вопрос или гипотеза | да | A-18 | до 1000 |
| 10 | Цель | да | A-19 | до 700 |
| 11 | Методы | да | A-23 | несколько через `;` |
| 12 | Данные или доказательная база | да | A-24 | до 2000 |
| 13 | Планируемый результат | да | A-25 | код вида результата |
| 14 | Критерии результата | да | A-26 | несколько через `;` |
| 15 | Связь с общей темой | да | A-06 | до 500 |
| 16 | Режим публикации | да | A-15 | `none` / `project` / `results` / `all` |
| 17 | Команда | да | A-13 | `Ф. И. О.;роль;задача`, записи через `;` |
| 18 | Контрольные точки | да | A-35…A-38 | `название;дата;ответственный`, каждая с новой строки |
| 19 | Признаки полного маршрута | нет | T-01…T-06 | коды через `;` |
| 20 | Публичная аннотация | нет | A-04 | до 1000 |

### Форматы составных полей

**Команда:**

```
Иванов Иван Иванович|leader|руководитель проекта;Петрова И. И.|member|анализ данных
```

Роли: `leader`, `member`, `supervisor`, `curator`. Третья часть необязательна.

**Контрольные точки** — каждая на своей строке, внутри ячейки:

```
Подготовка методики|2027-03-31|Иванов Иван Иванович
Апробация на трёх факультетах|2027-09-30|Петрова И. И.
```

**Признаки полного маршрута:**

```
T-01;T-06
```

**Виды результата:** `publication`, `methodology`, `model`, `dataset`,
`digital_product`, `grant_application`, `implementation`, `other`.

### Поддерживаемые форматы файла

XLSX (основной) и CSV (дополнительный, п.7.2 п.2). CSV разделяется точкой с
запятой, кодировка UTF-8.

Названия колонок должны **совпадать** с шаблоном. Лишние колонки игнорируются;
отсутствующие приводят к отказу с перечнем недостающих — иначе данные молча
уехали бы не туда.

## 3. Порядок импорта

### Шаг 1. Получите справочники

```bash
# Программы
curl -s -H "Authorization: Bearer $TOKEN" \
  "https://science.iubip.ru/api/programs?limit=100" | \
  python -c "import json,sys; [print(p['code'], p['title']) for p in json.load(sys.stdin)['items']]"
```

### Шаг 2. Заполните файл

Возьмите шаблон и следуйте примеру на втором листе.

### Шаг 3. Проверьте файл

**«Импорт и выгрузка» → «Проверить файл».**

До подтверждения **рабочие данные не изменяются** (п.7.2 п.4). Вы увидите:

| Показатель | Значение |
|---|---|
| Строк всего | сколько строк прочитано |
| Корректных | готовы к загрузке |
| С предупреждениями | загрузятся, но проверьте |
| С ошибками | **не загрузятся** |
| Возможных дублей | проверьте вручную |

По каждой строке — протокол с **названием поля и причиной**:

| Строка | Статус | Протокол |
|---|---|---|
| 3 | ошибка | **Код программы**: программа «НП-09» не найдена; допускается только действующая программа |
| 5 | ошибка | **Плановое начало**: дата «15.03.2026» не распознана (ожидается ГГГГ-ММ-ДД) |
| 7 | предупреждение | Руководитель «Сидоров А. А.» не найден в справочнике — профиль будет создан |
| 9 | дубль | РНП-2026-0003 — Совпадают название, авторы и год |

Строки с ошибками не загружаются (п.7.2 п.5). Исправьте их и загрузите файл
заново — остальные строки при этом тоже будут проверены повторно.

### Шаг 4. Подтвердите загрузку

**«Подтвердить загрузку».**

### Шаг 5. Проверьте результат

Каждая загрузка получает идентификатор пакета, дату, автора и протокол
(п.7.2 п.6). Пакеты видны в разделе «Импорт и выгрузка» → «Пакеты импорта».

Проверьте первые несколько карточек:

- заполнены ли обязательные поля;
- назначен ли руководитель и создан ли его профиль;
- создана ли команда;
- созданы ли контрольные точки;
- определён ли маршрут и записаны ли основания T-01…T-06.

## 4. Правила, действующие при загрузке

### Профили людей не дублируются

Человек сопоставляется по служебному адресу, затем по Ф. И. О. (FR-03,
п.6.1 п.2). Если профиль найден, используется он; если нет — создаётся новый.

Один человек в пяти проектах — **один профиль**, а не пять.

### Программы не создаются автоматически

Код программы в файле должен существовать в справочнике. Неизвестный код —
ошибка строки, а не повод создать программу: иначе в портфеле появятся
почти одинаковые программы с различиями в написании.

### Ответственный контрольной точки

Должен быть участником проекта (A-37). При загрузке он добавляется в команду
автоматически, если ещё не добавлен, — иначе точка осталась бы без
ответственного.

### Номер проекта

Присваивается автоматически, `РНП-ГГГГ-НННН`, и не переиспользуется. Номера из
файла, если они там есть, игнорируются.

### Публичность

Режим публикации из файла **не равен** разрешению на публикацию. Карточки с
режимом `project` или `all` получают отметку о разрешении, но в открытый контур
попадают только после отдельного разрешения уполномоченного лица.

Это осознанное разделение: импорт выполняет секретарь, а разрешение на публикацию
даёт проректор или куратор (п.9.2).

---

## 5. Защита от обрезанного файла

Если вы знаете, сколько строк должно быть в файле, укажите это в поле
«Ожидаемое число строк». При несовпадении загрузка прервётся с явным
сообщением.

Причина: повреждённый или недописанный файл XLSX обычно **открывается** и
отдаёт половину данных. Без такой проверки часть инициатив молча не попала бы в
реестр, и обнаружилось бы это через месяц при сверке.

---

## 6. Отмена загрузки

Отмены загрузки нет. Если файл оказался не тот:

1. Найдите пакет в списке — там сохранён протокол и автор.
2. Удалите созданные карточки через **архивирование** с указанием основания
   (FR-31).

Физическое удаление из интерфейса запрещено намеренно (п.10.1 п.3): архивирование
сохраняет связи и историю, удаление их разрушило бы.

Повторная загрузка того же файла **создаст вторые карточки** — система
предупредит о дублях в предпросмотре, но решение остаётся за человеком.
Поэтому проверяйте предпросмотр каждый раз.

## 7. Выгрузка

**«Импорт и выгрузка» → «Выгрузить XLSX» или «Выгрузить CSV».**

| Требование ТЗ | Как обеспечено |
|---|---|
| Учитываются права (FR-28) | Неуправленческая роль выгружает только проекты, в которых участвует |
| Учитываются активные фильтры | Применяются фильтры из раздела «Проекты» |
| Дата формирования (п.7.2 п.7) | Лист «Условия выгрузки»: дата, время, пользователь, роли, фильтры, число записей |
| Только доступные поля (п.7.2 п.7) | Категории из п.9.2 исключены для всех, кроме технического администратора |

### Форматы

- **XLSX** — основной. Формулы из данных экранируются: значение, начинающееся
  с `=`, `+`, `-` или `@`, выводится с префиксом, иначе Excel выполнил бы его
  как формулу.
- **CSV** — разделитель `;`, кодировка UTF-8 **с BOM**: без BOM Excel открывает
  кириллицу неверно. Если файл всё же открылся не так, выберите «Данные → из
  текстового файла → UTF-8».

### Архивная выгрузка

Полная архивная выгрузка структурированных данных доступна только техническому
администратору (п.7.2 п.8). Она включает категории, исключённые из обычной
выгрузки, поэтому её результат нельзя раздавать пользователям.

## 8. Технические детали

### Маршруты

```
GET  /api/import/template          шаблон формы
POST /api/import/preview           предпросмотр и подтверждение
GET  /api/import/batches           список пакетов
GET  /api/import/batches/{id}      протокол пакета
GET  /api/export/projects          выгрузка проектов
GET  /api/export/results           выгрузка результатов
```

`POST /api/import/preview` — мультипарт-форма: `file` и `confirm`, необязательно
`expected_rows`.

| Параметр | Назначение |
|---|---|
| `file` | Файл XLSX или CSV |
| `confirm` | `false` — предпросмотр, `true` — загрузка |
| `expected_rows` | Ожидаемое число строк; расхождение прерывает загрузку |

### Права

Импорт: технический администратор, секретарь, проректор по науке.
Архивная выгрузка: только технический администратор.

### Ошибки формата файла

| Ошибка | Причина |
|---|---|
| `Файл не соответствует утверждённой форме` | Названия колонок не совпадают с шаблоном |
| `Файл прочитан не полностью` | Файл обрезан или повреждён |
| `Файл не читается как XLSX` | Файл не является книгой Excel |
| `Файл пуст` | Нет ни одной строки с данными |
| `Поддерживаются форматы XLSX и CSV` | Отправлен другой формат |

Все сообщения перечисляют недостающие колонки — файл можно исправить, не
догадываясь о причине.
