# Словарь полей электронной карточки проекта

Приложение А технического задания версии 1.0 от 06.10.2026.

Обозначения обязательности: **О** — обязательное, **У** — условно обязательное, **Н** — необязательное, **А** — формируется автоматически.

Столбцы **Упрощённый** и **Полный** — разные наборы требований для двух маршрутов. Столбец **Открыто** означает, что поле может быть передано в публичный раздел — но только после отдельного разрешения уполномоченного лица (п.9.2 ТЗ).

Всего полей: **69**.

## Условно обязательные поля

Поле требуется, только если включён соответствующий признак. Признак T-02 (персональные данные, участие людей, этическое рассмотрение) сам по себе переводит проект на полный маршрут.

| Признак | Что требуется дополнительно |
|---|---|
| `flag_personal_data` | Указаны персональные данные — нужно пояснение (A-30) |
| `flag_human_subjects` | Участие людей в исследовании — нужно пояснение (A-31) |
| `flag_ethics_required` | Требуется этическое рассмотрение — укажите правовое и этическое основание (A-32) |
| `flag_confidential` | Указана конфиденциальность — нужно описание режима (A-33) |
| `flag_ip_restricted` | Ограничение прав — нужна поясняющая запись (A-33) |
| `flag_extra_resources` | Запрошены ресурсы сверх лимита — нужен ресурсный запрос (A-34) |
| `publish_mode` = `project` или `all` | Публичная аннотация (A-04) |
| `route` = `full` | Основания полного маршрута (A-08) |

## Шесть обязательных научных полей

П.4.2 ТЗ требует для запуска упрощённого проекта «шесть обязательных научных полей», не перечисляя их. Приняты шесть полей раздела «Научное содержание», отвечающих принципу «Проверяемый результат» (п.2.3 ТЗ):

1. **Исследовательская проблема** (A-17, поле `problem`)
2. **Вопрос или гипотеза** (A-18, поле `question`)
3. **Цель** (A-19, поле `goal`)
4. **Методы** (A-23, поле `methods`)
5. **Данные или доказательная база** (A-24, поле `data_basis`)
6. **Критерии результата** (A-26, поле `result_criteria`)

Плановый тип результата (A-25) проверяется вместе с критериями результата (A-26) как один смысловой блок — «планируемый результат с критерием».

Набор вынесен в код (`domain/validation.py`) и потому может быть уточнён без выпуска новой версии приложения.
